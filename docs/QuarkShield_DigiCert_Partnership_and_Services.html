1. Executive Summary

As global organizations face regulatory mandates (NIST, OMB M-23-02, CNSA 2.0, DORA, PCI-DSS 4.0) to migrate from legacy public-key cryptography (RSA, ECC, Diffie-Hellman) to Post-Quantum Cryptography (PQC), enterprise security leaders require both PKI issuance/lifecycle management and deep cryptographic observability.

DigiCert is the undisputed market leader in Certificate Authority (CA) infrastructure, issuing public/private certificates and automating web/load balancer lifecycle management. In late 2024 / 2025, DigiCert launched DigiCert Quantum Central to track quantum readiness.

However, DigiCert’s discovery architecture is inherently network-centric and cloud-vault-centric. It lacks visibility into local developer endpoints, workstation keychains, local keystores, and pre-build source code repositories. QuarkShield.ai fills this exact gap, providing the host agent and code scanner that feeds comprehensive CycloneDX 1.6 Cryptographic Bills of Materials (CBOMs) into DigiCert.

4. DigiCert’s Inherent Blind Spots

  • Local Endpoint & Workstation "Shadow Crypto": Network scanners cannot inspect internal developer MacBooks, Windows workstations, or build runners. Local user SSH keys (~/.ssh/id_rsa), Java KeyStores (.jks), local client certificates, and VPN tunnel configs remain completely dark to DigiCert.
  • Pre-Build Source Code Cryptographic Debt: DigiCert Software Trust Manager signs compiled binaries, but cannot scan source code repositories prior to compilation for hardcoded classical algorithms (e.g. RSA-2048 encryptors, deprecated TLS cipher suites).
  • Host-Level Configuration Remediation: While DigiCert can issue a post-quantum certificate, it does not reconfigure host daemons (e.g., configuring OpenSSH 9.8+ for mlkem768x25519 hybrid key exchange or patching NGINX cipher suites).
